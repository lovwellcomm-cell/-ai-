# 深度度量标准

这份标准把「有深度的回答」那份细则（准确性 / 完整性 / 逻辑链 / 证据 / 解释层次 / 信息密度）
翻译成能跑的检查。它不重新发明准则，只回答一个问题：

> **细则里的这一条，在这个系统里到底能不能被机器判定？**

答案是：**能判定的比预想的少**。下面每一条都标了可信度，并写明它**具体测不到什么**。
没有这个标签，代理信号就会被当成硬判定用 —— 而这个项目已经因为"指标骗人"栽过两次。

实现见 `tools/eval_rubric.py`（检查）、`tools/rubric_questions.py`（人工锚点）、
`tools/eval_depth.py`（跑测量）。

---

## 结构：准确性是否决项，其余五条并列

细则自己写了「一个事实出错，深度判定失败」—— 所以准确性是**门禁**，不参与加权。

其余五条**各自出数、不合成总分**。理由：

1. 权重是编的。任何加权都把"我编的权重"伪装成"测出来的精度"。
2. 这个语料里**没有已知的坏样本**（1099 个金额里 4 个存疑，全是已记录的多项合计限制），
   所以总分的"变化"只会是噪声 —— 而分数一旦存在，第一件事就是有人去优化它。
3. 可比性来自**固定的列**，不来自求和。同一批问题在不同配置下的回答并排看，就够了。

## 逐条

| 细则 | 信号 | 判定 | 可信度 |
|---|---|---|---|
| **1 准确性** | 有据可依率 | 每个金额能在片段找到出处，或由片段数字按明确算式推出 | 硬判定 |
| | 越界引用数 | `[n]` 中 n 超出片段数 = 虚构来源 | 硬判定 |
| | 非原文引文 | 转述式引文是否逐字出现在片段里 | 硬判定 |
| **2 完整性** | 锚点 n/m | 每题冻结的子问题骨架是否齐 | **代理信号（下限）** |
| | 口径缺注 | 只引用到母公司口径却没注明 | 硬判定（条件触发） |
| **3 逻辑链** | 换算一致 m/n | `246.74亿元（24,673,670,269.16元）` 括号原值 ÷1e8 是否等于前面的亿元值 | 硬判定 |
| | 自算不一致 m/n | 模型自己算的比率，能否用它自己引用的数字复现 | 硬判定（**抓不全**） |
| **4 证据** | 无引用条目清单 | 看起来是观点、却一点依据都不带的条目 | 硬判定 → **只出清单** |
| **5 解释层次** | 无据归因清单 | 给了归因、却没给任何依据的句子 | **绊线，不是度量** |
| | 推断式归因清单 | 「据片段数据推断」+ 因果词同时出现 —— 给编造的因果打掩护 | 绊线（扩展分析专用） |
| **6 信息密度** | — | **没有诚实的确定性实现** | **未核** |

台账层的几个数字（耗时、命中片段数、章节数、年份数、数字密度）是流水账，不是判断。
特别提醒：`引用命中率` 对「覆盖」那道题恒为 **0.29**，那只是 `分点依据：` 这行被当成了一句
没有引用的话，**不是质量信号**，别拿它下结论。

### 唯一允许的"率"是有据可依率

其余一律出**计数 + 清单**。一个含分母的漂亮数字，会在没人注意分母的时候变成结论 ——
`引用命中率 0.29` 就是这么被当成质量信号读的。`有据可依率` 是例外，因为它总是和
分母 `金额个数` 印在同一行。

## 实测校准结果

拿 5 组配置 × 6 道题 = **30 份真实回答**（401 句 / 1099 个金额 / 215 个条目）跑了一遍：

| 信号 | 结果 |
|---|---|
| 有据可依率 | 999 直接有出处 + 96 可推导，**4 个无出处**（全是同一个 7 项合计，逐项都可追溯） |
| 越界引用 | **0**（30 份回答，零虚构来源） |
| 换算一致 | **233 / 233** —— 这个房子的算术是扎实的 |
| 自算不一致 | **1 / 20** —— 见下，是真错 |
| 锚点 | 6 道题**全部 5/5**，横跨回答长度相差 24 倍的配置 |
| 无引用条目 | 0 |
| 无据归因 | 0 |

### 抓到的那一个真错误

`eval_out/followup-1016-2226.md`，跨表：

> 增加 35.36 亿元（3,536,050,047.18 元，据片段数字计算），增幅约 **15.56%**（据片段数字计算）

而 3,536,050,047.18 ÷ 22,739,727,998.27 = **15.5501%**。同一份年报、同一个量，
`baseline` 那组算的是 **15.55%**。差 0.01 个百分点 —— 是模型自己算错了。

### 重跑一轮之后（`eval_out/rubric-1016-2354`）

拿当前配置重跑了一遍，并**从 json 离线复算**（只读存下来的 `hit_texts`，不碰网络）：

| | |
|---|---|
| 有据可依率 | 6 道题全部 **1.0**（118 个金额，0 个无出处） |
| 换算一致 | **34 / 34** |
| 转述引文 | 2 条，**全部逐字命中** |
| 越界引用 / 无引用条目 / 无据归因 / 自算不一致 | **0** |

这一轮又抓出**两个我自己的误报**，都是旧语料里没出现过的写法：

- `23,882,535,292.17元（238.83亿元）` —— 原值和亿元**顺序反过来**写。容差原本只按外侧精度算，
  于是变成 ±0.005 **元**，等于要求分毫不差。
- `以上为合并报表口径。` —— 排除规则只写了「以上均为/以上都是」。

**这就是为什么必须重跑**：不重新生成语料，这两个形态永远暴露不出来。
凡改检查，都要在同一批问题上重跑一遍再下结论。

> 注：`eval_out/` 里 2026-10-16 早期的 5 份 `.md` 出自不同版本的脚本，**表格列不一样**，
> 横向比数字会误导。要比就比 `.json`。早期语料没存 `hit_texts`，
> 所以依赖片段的检查无法回算 —— 现在存了。

### 校准的诚实结论

**这套检查几乎没有分辨力。** 除了上面那一个算错，所有信号在 5 组配置之间是**恒定**的。
它分辨不出 baseline 和 budget600 哪个"更深度"。

所以它的定位是**回归护栏**，不是深度计：它能保证以后的改动**不会让回答开始编造来源、
算错账、或给出没有依据的归因**。这本身有价值 —— 但谁要是拿它说"这一版更深了"，那是假的。

## 被否掉的检查（以及为什么）

设计时想做的检查比留下的多。下面这些是**拿真实数据试过、发现会骗人**才砍掉的 ——
留一条会乱响的检查，比少一条糟得多。

| 曾想做 | 实测结果 |
|---|---|
| 引文核对（查全部引号） | 58 条引文 **18 条对不上（31%）**，全部合法：引自己的结论、引用用户原话、引提示词自己的词。收窄到转述式引文后才可用 |
| 「每个亿元都必须带括号原值」 | 280 处单位里 **42 处（15%）** 合法地不带：结论行、推导值、列举 |
| 算式可复现率（操作数有没有出现在回答里） | 比 `eval_fidelity` 已有的推导检查**严格更弱**：句子级误报、条目级漏报、回答级恒真 |
| 断言率（断言不得多于有证据的观点） | 215 个条目里被标出的**全部合法**（结论行、结构标签、口径说明）。按"任何数字都算证据"又会让真断言漏网 —— 两种口径都不对 |
| 归因有据率 | 17 个被标出的因果句里 **16 个是模型在正确地说"年报未披露原因"** —— 专门惩罚诚实 |
| 空洞句黑名单 | 30 份回答里 **0 命中**，纯空转 |
| 空洞句冗余检测 | 去掉数字后有 **49/401** 被标出，**全是承载最新数字的表格行** —— 与信息量反相关 |

## 没测到的部分

这些要人读，标准不假装测了：

- **准确性测的是「没超出检索到的片段」，不是「事实正确」。**
  细则原话是「用独立来源逐一验证」，但这个系统唯一能拿到的独立来源就是年报本身。
  年报本身有错、或模型把年报读反了，这里一条都抓不到。
  实测有一处正是这样：`tier0/追问-2` 明说递延所得税表头被截断、分不清哪列是 2024 ——
  如果模型当时默默选错了一列，检查器不可能发现。
- **第 5 条（解释层次）没有确定性实现。** 而且方向是反的：最好的「覆盖」类回答
  恰恰是**说「未披露」说得最多**的那些，任何"看它有没有讲因果"的启发式都会把它们判成最浅。
  保留的 `无据归因` 只是一根绊线，不是这条的度量。
- **第 6 条（信息密度）没有实现。** 见上表：两种做法都与信息量反相关或空转。
- **锚点是人写的**，带我的判断，且实测没有分辨力（恒为全中）。
- **`口径缺注` 在真实测量里从没触发过。** 6 道题都检索到了合并报表，所以「只找到母公司口径」
  这个前提一次都没成立。它只有单元测试钉着，**没有生产验证** —— 见到它一直显示 `-`
  不代表它没问题，只代表这个前提没出现过。
- **`无据归因` 会把「结论行里的归因」标出来。** 实测有一条：回答先给结论
  「从数据看，毛利率下降主要是成本增速高于收入」，紧接着的分点里每一条都带 `[1][2]` ——
  正是这句话的证据。但检查是按句看的，看不到后面的分点。看到这类条目，先去后面找分点。
  **不打算放宽这条检查**：放宽它，真正没有依据的归因就会漏过去。
- **`自算不一致` 抓不全。** 回答里数字多的时候，某一对无关的数字可能偶然凑出那个比率，
  把真错误漏掉。这个方向安全（不会误告），但「0」不等于"没算错"。
  **约 70 个比率里有标记可查的只有 20 个，其余 50 个未核。**

## 怎么用

```bash
python -m pytest -q                      # 检查器自身有 28 条测试钉着误报边界
python tools/eval_depth.py --label x     # 跑一轮，输出 eval_out/x-<时间>.md|json
```

报告分两张表：**数字**是台账（耗时、检索、token），**细则**是上面这套检查。
凡是有清单列的（`无出处样例` / `无引用条目` / `无据归因` / `换算不一致`），
`.json` 里存的是原文，可以直接拿去看。

改了 `rag/` 或提示词之后，重跑一轮，对着细则表看有没有**新冒出来的红旗** ——
不是看它涨没涨分（它没有分）。
